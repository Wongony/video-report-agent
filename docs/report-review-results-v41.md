# DeepSeek V4.1 视觉开启后的重新评测

日期：2026-09-11。实验目录：`runs/report-eval-vision-v41/`。

## 结论

六次真实报告生成全部完成。三个 review 都调用一次 inspect_report，各返回三张图片，模型随后正常响应，最终报告与检查快照一致。相比此前 imagesReturned=0 的实验，这次视觉图片反馈链路确实可用。

三个 review 在检查后均没有修改报告，六份报告均未触发当前程序检查项。因此本轮没有观察到视觉检查发现并修复问题，不能宣称报告质量提升。保持按需开启，不改默认配置。

## 可核对的视觉证据

- 通过安装中的 Pi ModelRuntime 离线读取有效模型：`deepseek / deepseek-flash`，显示名 DeepSeek V4.1 Flash，`input=[text,image]`，`api=openai-completions`，目的地 `https://api.deepseek.com`，Pi 0.85.1。完整非敏感配置见 effective-model.json。
- 三次 inspect_report 的真实 toolResult 各含三个 image block；总计九张，为顶部、中间、底部截图。没有额外调用视觉模型。
- 使用同一已安装适配器的 convertMessages 对留存 message_end 离线重放，三例各产生三个 image_url 内容项，随后各有一次成功 assistant 响应。结果见 transport-replay.json。这是实际工具事件与适配器重放证据，不是原始 HTTP 抓包，也不声称能够验证服务端内部如何理解图片。
- 全部检查使用修复版 1.1，检查在独立预览上规范化简介样式，不修改 Agent 工作文件。所有 review 的 final_matches_last_inspection=true。

## 来源与页面抽查

这是助手对照转写和截图的抽查，未进行独立人工盲评或原视频听校，详细定位见 source-review.json。

- 英语数字：review 把含混的“11”明确写成 eleven 入门课程并补充课程编号解释；baseline 则改成 101，两种处理都没有回听核实。review 的 ten-four 强调框还新增“比整句复述更清晰、更省时”的比较，unit-000003/000004 没有这项依据。看到页面不等于解决了来源歧义。
- 以撒：两组保留充能前提、演示插头条件和资源循环。baseline 的循环组件把“其余转成金箱子”写成“其余转成金币”，与后面的开箱叙述不一致；review 初稿保留了金箱子，但该差异产生在检查前，不能归因于反馈修复。review 另把 unit-000062 含混的“有这个视频的话”改为“有的道具一旦到手”，增加了未经支持的条件。
- AI 学习：两组覆盖单一界面聚合多来源、保留学习材料上的努力、探查—规划—教学及反馈，也保留演示故障。baseline 把含混的 pient/py/ob 统一解释成 Obsidian，属于尚未确认的产品归属；review 较少强调环境名，但仍有 Skill 禁用的对照句式。未将这些内容问题伪装成程序检查结果。
- 中段截图抽查：六份可读，未见明显横向溢出。review 英语数字用了并排卡片，以撒用分组列表，AI 学习把反馈单独成章；这些是初稿组织差异，无检查后修订，不能据此建立工具的视觉提升因果。三张视口图片也不能代表逐像素审阅了长报告全页。
