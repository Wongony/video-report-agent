# 报告检查与最小评测 V1

## 目标

给现有 Pi 单 Agent 增加 `inspect_report`：读取当前 HTML 的真实浏览器结果，定位可操作问题，允许同一次生成内局部修正。以固定本地转写做 baseline / review 对照，判断收益及耗时成本。Pi 继续拥有 agent loop，不增加 Planner、Critic、独立评审模型或多 Agent 编排。

本轮用户明确授权该检查与修订能力；它是对历史“不增加 revision workflows”约束的这一项小范围更新，不授权重建历史证据系统。

## 检查边界

- 920px 桌面画布，与现有导出保持一致。
- 检查横向越界、明确 overflow:hidden/clip 下的纵向裁切候选、缺图和资源/脚本错误。
- 检查 `data-source-units` 是否引用当前 transcript.md 中存在的 ID；缺少绑定会提示。不会判断引用是否语义支持结论，也不会根据覆盖数量评分。
- 折叠内容不计可见版面越界。裁切提示是候选，装饰性隐藏不必修改。
- 每次保存未修改的 `source.html`，在独立 `report.html` 快照上应用现有交付简介样式处理，再生成顶部/中间/底部截图、全页图和 JSON 结果。不会修改 Agent 工作文件；截图每次重新生成，不使用旧缓存。
- 模型支持图片输入时，工具直接返回三张截图；否则返回程序检查和图片路径，不声称模型已经看图。
- 同一 Pi 会话最多两次工具检查，每次工具执行 90 秒上限；指令允许一次集中修订，第二次检查后停止修改。工具调用次数硬限制，编辑次数是 Agent 指令约束，不能当成 OS 级限制。
- 检查错误会记录为 error，不等同于无问题。工具报告 checked 也只表示程序检查完成。
- 保留现有来源、纯白报告纸面及手机整体缩放契约。不改 ASR、OCR、原始转写，不做网页搜索、RAG 问答、跨视频知识库或新主题系统。

## 最小数据集

见 `evals/report-review/manifest.json`。三份完整本地转写及公开元数据已固定到 materials，避免后续清理 runs 影响复现。

1. numbers：英语数字短讲，短篇并列概念；含数字/英文 ASR 歧义。
2. isaac：资源转换与操作教程；需保留充能前提和演示条件，术语噪声明显。
3. learning：较长学习方法论和实操；需区分单一界面与多来源，保留反馈机制和作者体验归属。

每例有来源 ID 支持的内容检查点。这些是基于现有转写整理的审阅提示，不是人工听校后的 gold transcript；不能据此评估 ASR 准确率。数据集规模只支持开发 smoke / 初步对照，不是泛化质量基准，也没有独立 holdout。

## 运行

功能默认关闭以保持现有生成行为。设置 `REPORT_REVIEW=1` 后启动服务或 CLI 即启用；无需改 Skill。`PiRunner(review=True/False)` 可在程序中显式选择，评测入口会显式比较两种模式，不受该环境变量影响。未取得质量收益证据前不默认推广。

```sh
UV_CACHE_DIR=/tmp/video-report-uv uv run python -m video_report_agent.evaluate_report \
  --output runs/report-eval-NEW --timeout 600
```

输出目录必须不存在，避免覆盖历史实验。默认每例 baseline/review 各一次，共六次模型生成。仅使用当前项目模型配置，保留同一 Skill 和完整输入；按案例交替两组先后次序。`--repeats 2` 可运行两组重复实验，需自行确认相应费用。

该入口只从固定 transcript 生成报告，不调用下载、ASR 或 OCR。模型请求会将这些公开素材转写发给当前配置服务，usage 中价格不可用时保持 unknown；估算费用不等于实际账单。

baseline 仍保留原 Skill 的自检指令，但没有 inspect_report 工具或追加检查指令；review 增加工具和反馈要求。因此实验比较“检查工具+使用指令”这一整项增量，不单独归因于截图或某一句 prompt。

每次生成沿用 PiRunner 的总超时，本实验设为 600 秒，包括检查和修订。最终离线检查另计，不反馈给 baseline。一次真实生成失败不自动重试。

## 结果与验收

- invocation、Pi 事件、原始 usage、每次检查前的 HTML 和截图均留在实验目录。
- results.json 记录完成/失败、生成耗时、工具调用次数、最终报告是否匹配最后检查、问题候选数和可获得的 token/估算成本。
- 问题数按元素统计，嵌套元素可能重复指向同一个版面问题，不直接称为缺陷率。
- 自动结果不打语义或审美总分。人工按 manifest 的检查点对照来源，记录错误位置、原文依据、修复后是否引入新错误；页面检查层级、密度、解释是否清楚。
- 自动测试验证真实浏览器能发现构造的缺陷并识别修复，不能代替真实模型 E2E。
- 验收真实 loop 必须看到 inspect_report tool result、后续修改和重新检查；如果原报告无问题，无修改也属合理行为，不能编造修复收益。
- 若样本没有改善或增加较多耗时，应保留结果，不宣称 review 提升质量。是否默认推广由真实证据决定。
