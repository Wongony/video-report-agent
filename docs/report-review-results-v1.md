# 首轮检查接入与三例评测结果

日期：2026-09-11。目标与边界见 [report-review-v1.md](report-review-v1.md)。

## 结论

原生 `inspect_report` 工具已经进入 Pi 的 active tools，真实模型运行中可调用。修复版 1.1 不修改 Agent 工作文件；在最后一个真实案例中走通检查、局部编辑和复检，最终交付与最后检查快照一致。功能通过 `REPORT_REVIEW=1` 按需启用，默认保留原行为。

尚无“报告质量稳定提升”的证据：六份最终报告均未命中程序检查项，当前模型未收到图片，且第一轮包含检查器版本修复。没有执行人工评分或独立语义评审。

baseline 仍可用 bash/read 自行检查，原 Skill 也要求自检。这里比较的是增加命名工具与使用指令的增量，不是“完全不检查”与“检查”的比较。所有素材各一组，顺序交替，无重复采样、没有独立 holdout，不能得出稳定耗时或质量排名。

## 本轮发现并修复的问题

初版检查器调用现有简介规范化函数时改变了 Agent 的 report.html。以撒案例中，Agent 发现被自动添加的属性/CSS 与写作指令不一致，于是移除，下一次检查又加回来。检查本身因此制造了工作。

1.1 保存未修改的 source.html，只在独立 report.html 预览快照上做交付阶段同样的样式处理。浏览器用该快照作为页面，但继续从本次 run 的 assets 读取素材。新增真实浏览器回归测试证明原文件不变。

保留初版结果不覆盖、不重跑模型。最后一个 review 使用 1.1，不能把前两例也标成修复版 E2E。另用 1.1 对全部六份最终报告完成本地只读重检，全部 checked、程序问题候选为 0，且原文件字节保持不变。

AI 学习案例的三处实际修订是移除 Skill 禁用的对照句式；两次程序检查本来均无告警。因此只能证明模型在两次检查之间进行了文风修订，不能把这些修改归因于程序缺陷检测，更不能宣称修好了三处版面问题。
