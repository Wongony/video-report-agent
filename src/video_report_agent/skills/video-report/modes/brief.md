# 精简速览（brief）

仅在任务选择 `brief` 时读取。完整理解原始转写，独立编辑一份**大标题、清晰编号、少量重点、直接可读**的速览。读者应能从章节标题抓住主线，再读必要依据与条件。不先生成 Standard 再压缩，不把原视频逐章缩写成卡片长卷。

只读取 [Brief 模板](../assets/brief-report-template.html)，使用其内联 CSS 与 `brief-` 组件，不读取另一模式或其模板。公共来源准确性规则始终适用；公共完整解释要求仅适用于本模式选中的核心内容，不据此补回全部细节。

## 先形成主线，再写正文

1. 完整读完来源，确定读者最需要回答的核心问题。围绕回答过程组织少量大章节；通常三至五组足以构成阅读骨架，多主题来源按实际关系调整，不强凑数量或因果。每章只解决一个主要问题，标题简短、具体，连起来能说明整篇如何推进。
2. 先选核心判断、决定性依据和成立条件。主要主题保留核心含义即可，不要求各自开章；背景知识、组织机制、会议过程、辅助统计、历史例子和行情明细默认省略，只有省略会误解核心判断时才就地保留最少解释。
3. 同一事实、数字、机制或建议只展开一次。影响分析与个人应对合并重叠材料，图中已表达的关系不再逐项解释。时间线只在事件先后本身是核心问题时使用，不把叙述过程变成步骤墙。

新闻背景用开头短说明交代，不先展开一整节行情或术语课。写前判断“这项内容改变哪个核心答案”；答不出来就省略。篇幅通过取舍变短，不通过小字、窄列或高密度信息压缩变短。常见单一核心问题的速览，以约 800–1200 个汉字的正文作为编辑起点（含图表，不含来源）；复杂材料只为不可缺的判断与条件适度增加。此范围用于主动取舍，不是截断上限，绝不能为凑字数删除事实限定。调用方要求“完整报告”指可独立阅读、结构完整，不要求内容详尽。

## 固定的阅读骨架

- 保留醒目的主标题、简短导语、完整来源与原有页尾。导语用一两句交代对象和核心问题，不列目录；副标题无新增含义时省略。
- 大章节使用 `.brief-section > h2`，模板自动显示 `01、02、03` 章节编号，作为阅读定位，不暗示因果或操作顺序。不要手工重复编号，不取消章节大标题。章内不再多层编号或堆叠小标题。
- **Brief 正文不显示时间戳**：不生成 `.section-time`，不在图表、章节旁或说明中另写来源时间。保留隐藏的 `data-source-units` 与页尾折叠来源说明，需要回查时依靠来源绑定。Standard 的章节时间戳规则不用于本模式。
- 每章采用一个清楚的主要表达，再补必要条件即可；通常总计两三个短段或条目就能说明，不在章节内部继续铺开多套机制、数据和事件。优先使用简短正文、重点结论卡或真正的双栏对照；不要在同一章连续轮换数字条、旁注、表格、流程和卡片。
- 并列内容不必做成卡片；彩色卡片只强调核心判断或对照。保持白底、原有字体和浅亮配色，相同语义使用相同颜色，不以颜色暗示来源没有支持的优劣。

## 少量层级，避免小字

- 保持模板字号：主标题 38px、带编号章节标题 30px、卡片标题 22px、正文与必要说明 18px。来源字段和页尾可略小；正文、数字口径、条件、表格、图注与图内标签不能降为小字。
- 必要限定直接放在对应判断的句子或紧邻正文中，以同样字号阅读。不要把整段重要内容降为灰色小字旁注，也不要用左侧短标签加右侧长段落的形式挤出窄栏。
- 标题负责导航，正文只对关键判断或词语加粗。数字与对象、单位、基准一起读，不把每个数字放大成独立视觉焦点。
- 卡片解释通常一至两句。超过三行先删除重复和旁支；决定性限定确需更多空间时保留，但不借例外塞入完整推导。不得 CSS 截断、固定高度遮挡、机械换行或缩字号。
- 主要靠留白、对齐和章节编号分组。条件、数字、步骤与补充说明不加装饰线。只有表达真实方向的图示才使用连线；表格只在跨行比较比文字更清楚时使用。

## 组件按需使用

`.brief-feature` 承载一个重点结论；`.brief-pair > .brief-card` 承载同维度的对照；短条目可用 `.brief-list`。必要时用 `.brief-map` 表达真实关系、`.brief-flow` 表达必要操作顺序、`.brief-table` 做简短比较。图不表达来源之外的关系，标签按实际显示宽度保持可读，放不下先简化图的内容。

表格单元格只放短判断和口径，不能承载多句长解释；不把已有正文换一种形式重复到表格里。图只保留理解主线必要的节点，数字与背景不得逐项塞进图；图内文字沿用模板可读字号，放不下就减少节点或改为短条目，不能自行设小字号。

`.brief-condition`、`.brief-note`、`.brief-caption`、`.brief-facts` 等只是同字号辅助排版，不是必须填满的内容槽位。能自然写进判断的限定、数字和依据直接合并，不为这些组件另造一层解释。模板示例是合成演示，删除后填入真实内容，不照搬示例的章节数量与组合。

## 不可压掉的事实边界

- 保留主体、说话人归属、成立条件、否定、因果方向、数字单位与基准以及“约”等口径。具体算例不泛化为任意条件成立的公式。
- 预测、经验、类比与作者观点保留其性质，不写成确定事实或已验证结果；标题和图同样遵守。遇到识别含混的非核心数字，省略该例而不猜测修复。
- 关键依据足以支持判断；可省略次要案例，一旦保留就带齐决定性条件。不能将限定统一挪到页尾或折叠区。
- `data-source-units` 逐个列出真实存在且实际支持内容的 ID，以空格分隔。禁止区间、通配符、自造 ID 或整篇 ID 替代逐处绑定；无原生 ID 时按公共规则建立逐段映射。ID 有效不代表语义准确。

## 交付前集中修订

先只读主标题和编号章节标题：能否看出整篇的核心问题和推进方向？再读最密集处：是否仍有小字说明、过多局部标题、长段卡片、重复例子或非必要时间线？若仍像原视频逐章摘要，回到主线合并和取舍，不靠继续换组件解决。

核对标题、关键数字、图中关系和建议的来源、归属与限定；确认没有正文时间戳。以约 900px 桌面查看顶部、复杂区与结尾，实际确认标题和编号醒目、正文说明可读、没有溢出或图文重叠。不以字数、图片高度或检查通过证明速览质量，不写未执行的检查声明。
