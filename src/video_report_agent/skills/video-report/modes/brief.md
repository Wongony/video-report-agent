# 精简速览（brief）

仅在本次任务选择 `brief` 时读取。从完整原始转写独立编辑一份**以紧凑卡片、关系图、对照和短条目为主体**的速览，帮助读者扫读主要主题、核心结论与关键关系。不要读取标准模式，不先生成标准报告再压缩。

本文件决定内容范围和展开程度。公共规则中“完整解释、必要例子、连贯段落”等要求，均在本模式选定的核心内容范围内适用；不能据此把原视频的全部解释、演示和例子补回。公共来源准确性规则始终成立。

## 模板与组件边界

只读取 [Brief 模板](../assets/brief-report-template.html)，采用其中内联 CSS 与 `brief-` 组件。不要读取、引入或照抄 Standard 模板、长解释卡片或视觉示例；两版只共用来源准确性与交付约定。本模式下不能把单列长文章换成浅色底就交付。

## 先取舍内容，再组织模块

1. 完整理解来源，找出核心问题、主要主题及其连接。每个主要主题提炼直接回答问题的核心判断或关键路径，并找出会改变其含义的条件、依据和数字口径。
2. **主动省略次要展开**：辅助历史案例、重复类比、逐步演示复述、旁支术语和详细推导默认不进入正文。只有缺少它们就无法理解主线或会误解核心判断时才保留，保留最少的必要内容。不要逐段转述原视频，也不要仅合并章节、改短句子而仍覆盖全部细节。
3. 按实际关系组成内容模块。每组先给简明答案，再就地交代必要条件或依据；主图或对照已经讲清的内容，到此结束，不在后面重新展开一套解释。

复杂来源也按这个方法生成速览，不因复杂或视频较长切换标准版。时长不换算字数或组件数量，主要主题不能因精简而整组消失。理解主线必需的术语用短句就地解释，不留下孤立术语或半截结论。

## 引用硬约束

`data-source-units` 只允许逐个列出真实存在、实际支持本处内容的来源 ID，以空格分隔，例如 `unit-000013 unit-000014`。禁止 `unit-000013–unit-000020` 这类区间写法、通配符、自造 ID 或用整篇 ID 替代逐处绑定。没有原生 ID 的独立转写，沿用公共规则建立逐段映射，再引用实际映射 ID。交付前对照完整来源列表检查每个 ID；格式正确不替代语义核对。

## 不可压掉的事实边界

压缩可以删减、合并和降低展开程度，但不得增强来源中的因果、幅度、确定性或场景归属，也不得改变主体与关键数字口径。

- 主体与说话人归属、成立条件、关键限定、否定、因果方向、关键数字的单位与基准、“约”等口径就地保留。
- 预测、经验、类比与作者提出的理想方案保留原有性质。不能把“希望实现、认为有效”变成“已验证、必然有效”。
- 关键依据保留足以支撑判断的简短说明；需要保留的数字必须带齐对象与口径。精简不能把有条件的结论写成无条件保证。
- 可省略某个次要案例；一旦保留该案例或结论，就必须保留会改变其含义的前提和限制。

## 用结构承载正文

- 保留公共题头、短导语与完整来源，然后直接进入有效内容。导语也遵循短说明目标，不提前复述各章。无需重复的摘要、内容地图和结尾总结。
- 并列要点用紧凑卡片或列表，差异用对照，操作用步骤，因果与依赖用关系图。**正文主要由这些模块承载**，不能用长文章加少量插图交付速览。
- 一个卡片只承载一个结论，解释优先 1–2 句；必要条件与依据紧邻结论。多个结论按实际关系分组，不塞进同一句长句；步骤和因果保留连接，不把逻辑拆成孤立碎句。
- 图示和邻近文字分工明确：图表达关系，文字只补图中未承载的决定性条件或依据。不要把图中每个节点再逐项写成段落。
- 叙事确需衔接时可以使用短段落；不把完整论证、故事或演示原样装入卡片。组件不设数量要求。

## 短文本与视觉节奏

- 在约 900px 设计画布和模块实际宽度下检查正文。解释超过 3 行时，依次删除辅助例子、非必要机制细节和重复表述，再按解释重心重组；不得把多个信息硬塞进一句话，也不靠机械换行伪装短段。
- 必要限定放在对应判断旁，可单独用短条目完整表达；条件确实复杂时允许必要例外。例外不能扩展为全篇保持长段。
- 禁止 CSS 截断、固定高度遮挡、缩小字号或删除限定来满足行数。
- 加粗区分关键词、关键结论和必要条件；解释保持普通字重。小标题直接指出这一组讲什么，不靠全段粗体或底色冒充扫读层次。
- 共用题头、完整来源、页尾和交付约定；Brief 保持模板的白色正文底、原有字体与圆角卡片，采用浅亮的蓝、米黄、绿、珊瑚与紫做局部区分，保持高明度，仅适度降低饱和度，不加深或调成灰暗色块；不改为整页彩纸、深色题头或另一套刊物版式。正文以白色和深色文字为主，同类信息在全文保持同一配色；色彩不暗示来源未支持的优劣或风险。用结论卡、对照、短流程和就地条件组织内容，不使用 Standard 的单列长解释卡来容纳全部细节。卡片与留白匹配实际内容，不为填版面补文字。
- 不把全篇所有段落都装进彩色卡片。核心结论或必要对照用卡片，顺序用无底色流程线与编号，数字用口径条，跨维度比较用短表，补充与限制用无底色说明或关系图。按内容关系选择，不机械轮换组件或强凑数量；同一屏应能辨认主要结论与次要解释。

## 交付前按速览目标修订

检查最密集的阅读单元：若还在逐段讲解演示、类比、历史案例或技术推导，重新取舍内容；若主图后还有相同内容的整段解释，删除重复；若卡片装着长文，把它改为能扫读的判断与条件。

最后核对主要主题、关键关系与事实边界，再看短文本和粗体能否支持扫读。**长文章减少几个章节或少写一点字，不算合格速览。** 不用未执行的检查声明证明达标。

## 按信息关系选择 Brief 组件

模板中的示例是合成内容，只演示结构，生成时删除示例并填入真实来源。组件可按内容自由组合，不设配额，不要求每篇使用全部组件；没有合适组件时，在 Brief 的色彩、短文本与 `brief-` 命名边界内实现局部结构，不导入另一模式的组件。

| 组件 | 使用时机 | 内容边界与不适用场景 |
|---|---|---|
| `.brief-feature` 结论卡 | 一个核心判断需要优先看见 | 一个结论及必要条件，解释优先 1–2 句；不承载整章摘要或推导 |
| `.brief-pair > .brief-card` 对照 / 并列卡 | 按同一维度比较，或同主题下的独立要点 | 每卡一个结论，不把多种观点与例子塞进同卡；颜色区分角色，不表示优劣 |
| `.brief-condition` 条件条 | 某个结论存在决定性前提或例外 | 紧邻该结论；不能把全篇限定统一移到页尾 |
| `.brief-flow > .brief-step` 无底色编号流程 | 来源支持的先后顺序、必要步骤 | 每步写关键动作及条件；仅有顺序用编号，连接含阈值或分支时用 `.brief-path` 与 `.brief-connector` 写清条件；不是操作录像的逐步复述 |
| `.brief-facts` 数字与口径 | 关键数字本身需要扫读定位 | 数字、对象、单位、基准同行或邻近；不要放大所有零散数字 |
| `.brief-minor-pair` 无底色并列说明 | 两个次要要点需要并列阅读 | 不需要强调为核心结论时使用，不再外套彩色卡片 |
| `.brief-feedback` / `.brief-note` | 跨步骤反馈、必要补充与不确定性 | 不预设回到起点的闭环；说明与主图分工，不重复解释每个节点 |

需要跨行比较时使用 `.brief-table` 的短表；长解释不装进单元格。需要机制或上下文边界时使用 `.brief-map` 内的图解，标清对象、方向与条件，只画来源支持的关系。正文中的新增视觉类名仍以 `brief-` 开头，复用 Brief 色彩变量。

保留模板的字体大小、自然高度与内联样式；先改内容组织，再微调布局。不得以重写长文样式、增加固定高度或隐藏溢出来规避短说明目标。
