# Procedure：操作与条件选择

当主要理解任务是完成一个目标、执行操作或根据条件选择行动时使用。标题含“教程”或内容出现步骤，不足以决定此 Profile。

## 编辑重点

- 先交代目标、适用对象及必要的前置条件，再按实际依赖组织操作。
- 区分必需步骤、可选操作和条件分支；把影响行动的限制放在对应步骤附近。
- 来源提供时，保留结果判断、失败表现和对应处理，不自行补写排障手册。
- 快速掌握交代关键路径与决定性条件；内容地图展示流程和分支；深入阅读补充操作细节、原理与示例。

## 可选表达

线性操作使用有序列表或 `.steps`；确有条件选择时使用 Decision Tree，分支写清“条件—动作—结果”。前后效果可用 Before → Trigger → After；机制解释可自由使用关系图。

例如来源包含“准备环境、配置模型、创建会话、订阅后发起对话”：地图只呈现这些依赖与先后关系，并链接正文；安装命令、环境变量名和事件过滤代码留在对应步骤。不要把每个短节点扩成“标题＋整段说明＋单独一行导航”的高卡片，也不要把整套操作再次塞进快速掌握。

## 失真提醒

不把经验性建议写成必然成功的操作，不删除版本、资源、适用环境或失败条件。不将可选步骤强制化，也不将顺序依赖改成可互换的并列项目。
